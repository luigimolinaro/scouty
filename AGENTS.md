# AGENTS.md

This file provides guidance to agents when working with code in this repository.

## Stack and commands
- Zero-dependency Node.js 20 server ([`server.js`](server.js)) plus a vanilla JS SPA split in three static files: [`public/index.html`](public/index.html) (markup only), [`public/app.css`](public/app.css) (two lines: the base rules, then the `#sv` rules with the print CSS) and [`public/app.js`](public/app.js) (one IIFE). No bundler: they are served as they are. There is no `package.json`, bundler, linter, formatter or test suite. Do not add npm dependencies. Code and UI strings are in Italian.
- Run locally: `USERS='mister:pw:coach;luca:pw:scout' DATA_DIR=./data node server.js` (port 8080, `/healthz` for health). Without `USERS` it prints temporary credentials to the log.
- Hash a password: `node server.js hash '<pw>'` gives `scrypt$salt$hash`, which can go in `USERS` instead of a plaintext password.
- First install: `./setup.sh` ([`setup.sh`](setup.sh)) is idempotent. It creates `.env` from `.env.example` (dropping the sample `USERS`, and removing sample users from an existing `.env` with a `.env.bak`), creates `data/` and checks its owner, asks for the first coach via `users.sh add`, runs `docker compose up -d --build` and polls `/healthz` (on failure it prints the container logs and exits 1). Flags: `--https` (asks the domain, sets `DOMAIN`, `COOKIE_SECURE=1`, `TRUST_PROXY=1`, uses the `https` profile) and `--no-start`. `ENV_FILE=path` works here too.
- Docker by hand: `docker compose up -d --build`. HTTPS with Caddy: `docker compose --profile https up -d --build`. Both need a `.env` at the repo root (`env_file: .env`), which is git-ignored and never committed.
- Manage users with [`users.sh`](users.sh) (`list`, `roles`, `add`, `passwd`, `role`, `remove`, `apply`) instead of editing `USERS` by hand. It rewrites only the `USERS=` line of `.env` (single-quoted so compose does not expand the `$` in scrypt hashes), keeps a `.env.bak`, and stores passwords hashed. If `.env` is missing, `add` creates it from `.env.example`. Hashing uses `node`, or falls back to building and running the `scout-pallavolo:latest` Docker image. `ENV_FILE=path` overrides the file, which is useful for testing without touching the real `.env`.
- [`.env.example`](.env.example) is the template `users.sh add` copies to `.env` when it is missing. The image is still called `scout-pallavolo:latest` (used by `docker-compose.yml` and `users.sh`): do not rename it without updating both.
- The Dockerfile copies only `server.js` and `public/`. Any new server-side file must be added to the Dockerfile `COPY` lines.

## Server conventions ([`server.js`](server.js))
- All state is in-memory (`DB`, `MATCHES`, `IDX`, `LOCKS`) and written to `DATA_DIR` as `data.json`, `secret` and one file per archived match in `storico/YYYY/MM/<mid>.json` (year/month from the match `date`; an invalid date falls back to today). Always use `writeJson()` (tmp file + rename) and never write these files directly. `IDX` (mid -> summary + relative path) is rebuilt from the folders at startup; `putHist()`/`delHist()`/`getHist()` are the only functions that touch the archive (they also move the file when the date changes and remove empty folders), `HV` changes on every archive change. There is no history size limit and `HISTORY_SIZE` no longer exists. An old `history.json` is imported once and renamed `history.json.v1`. `mid` is validated by `isMid()` and the date by `okDate()`, so a path can never leave `storico/`.
- Several matches can be live at once, but only one per team (`busyTeam()`, compared case-insensitively) and at most `MAX_LIVE` (default 5). `data.json` is `{sqv, squads, matches:{mid:{ver,state}}}`: each match has its own `ver` counter, and squads have `sqv`. An old single-match `data.json` is converted on startup and a copy is kept as `data.json.v1`. `PUT /api/data` takes `m` (match id) and `base` and returns 409 with `conflict:true` if stale, `error:'lock'` if another session holds that match's lock, or `error:'team'`/`'max'` when a new match is refused.
- Each match has its own scout lock (`LOCKS`, keyed by `mid`), held by one session (`sid`). Every `/api/lock` call needs `m`. It expires after `LOCK_TTL`, which is at least 20 s and defaults to 90 s. Clients send `beat` every ~9 s (every third 3 s tick), `get`, `take` and `release` are the other actions, and `pagehide` sends a `release` beacon.
- Sessions are HMAC-signed cookies named `sv`. `readSession` rejects the cookie if the user was removed or their role changed, so editing `USERS` invalidates sessions.
- Roles are `coach`, `scoutman` and `scout`. `coach` and `scoutman` are equivalent for now (`isFull()` in `server.js`, `isCoach()` in `app.js`) and are the only ones receiving `hist` and using `GET`/`DELETE /api/history/:mid` (`DELETE` also requires holding the scout lock, 409 otherwise). `normRole` also accepts the aliases `allenatore` and `admin` for `coach`. When roles change, keep `valid_role`, `cmd_roles` and the last-admin check in [`users.sh`](users.sh), the role labels in `paintBars()` in `index.html`, and the README roles table in sync.
- Every non-GET API call must be `application/json` (415 otherwise). Body size limits are set per route in `readBody`. Handler errors return a generic `{error:'errore'}` and details go only to the server log.
- The CSP in `SEC_HEADERS` allows only `'self'`, inline script/style, and Google Fonts. Do not add external scripts, CDNs or analytics, because they would be blocked.
- Static fallback is SPA-style: any unknown GET path serves `index.html`.
- Real-time: `GET /api/events` is a Server-Sent Events stream (max `SSE_MAX` clients). `notify()` is called by `writeJson()` and by every lock change (`get`, `release`, `take`, logout) and sends `data: 1` (debounced 60 ms) plus a `: ping` every 25 s. The client (`openEvents()`) only uses it as a hint to run `pull()`; the 3 s `tick()` polling stays as a fallback and drops to every 15 s while the stream is open (`esOk`). Do not send data over SSE, clients must keep reading through `/api/data`.

## Frontend conventions ([`public/app.js`](public/app.js), [`public/app.css`](public/app.css))
- The whole app is one IIFE wrapped in `#sv`. Elements are looked up with `$('name')`, which resolves `[data-r=name]` inside `#sv`, not by id. Clicks are handled through `data-*` attributes (`data-v`, `data-fs`, `data-i`/`data-e`, and so on).
- CSS and JS are minified-style one-liners. Match the surrounding terse style when editing. Italian user-visible text uses `\uXXXX` escapes for accents and symbols, not literal characters.
- `localStorage` is allowed ONLY for the safety queue `scouty-pending` (`savePending()`/`clearPending()`/`restorePending()`): a copy of the match state with `{u,mid,base,t,state}`, written when a flush fails (offline), on `pagehide` with unsent changes, and on every `markDirty()` while `NET.off`; cleared on a successful flush, on conflict and in `lost()`. `start()` restores it only if the same user, the match is still live, the server `ver` equals `base` and nobody else holds the lock; otherwise it is discarded with a note. Never store anything else there. The `store` object keeps `state` and `squads` in memory (`MEM`/`SYNC`) and syncs them to the server through debounced `markDirty()`/`flush()`. Changing `S` requires `persist()`, which `render()` already calls. Add new persisted fields to both `persist()` and `freshMatch()`.
- Remote data is applied through `hydrate()`, which keeps local view state (`view`, `fs`, `f`, `so`, `si`, `rp`). Add any new local-only UI state to its `keep` list.
- The Scout tab with no open match (`S.phase==='setup'`) shows `liveView()`, the list of live matches (`NET.live`). Per card: `data-lv` resume/watch, `data-en` end (everyone, only when nobody is scouting, double tap, `endLive()`), `data-tl` take over (`isCoach()` only, double tap). `data-nm='1'` opens `pre()` (new match), where teams with a live match are disabled. Double taps use `armLm`, cleared by `disarm()`.
- Before changing match data, call `canWrite()` first. It returns false while another user holds the lock (read-only mode).
- Always pass user-supplied text through `esc()` before putting it in `innerHTML`.
- Events are stored as arrays `[playerIdx, fund, '+'|'/'|'-', set, role, pointTeam]`. Fundamentals are `BT`, `ATT`, `R`, `M` and `Fallo`. Rally history is `rally:[[set, team]]`. `sc` is a fixed array of 5 sets. A set ends at `tgt(s)` points with a 2-point lead, and 3 sets won archives the match.
- Excel export is hand-built SpreadsheetML XML (`xc`/`xr`/`xsheet`). PDF export is `window.print()` on the stats view. Do not add libraries for either.
- Efficiency thresholds live in `SQ[team].tgt` (`[effBT,effATT,effR,sideout,break]` fractions, defaults in `TDEF`, read via `tgtOf()`, which also drops the old muro value from legacy 6-item arrays), edited in the coach-only `tgtBox()`, opened by the "Edita efficienze" button (`data-te`, state `tgtOpen`) shown in the Squadra editor (`team()`; needs a saved squad, `S.sq`). While a squad is being edited (`edit` in `team()`) the squad picker and "Crea squadra" are hidden and `data-bk` goes back. `team()` wraps `team0()` in `.tr` and adds `in`/`inb` (slide animation) only when the sub-screen changes (`lastSc`); do not reuse the `.sw` class, it is the legend swatch; `applyTgt()` copies them into `TGT` at the start of `stat()` (so archived matches use their team's thresholds). The radar has 5 axes (BAT, ATT, R, S-O, B-P) built by `pos(r,s)`, with `POSREF===TGT`. `PUT /api/data` in `server.js` keeps the stored `tgt` when a non-`isFull` session sends squads. `d.sv` must preserve `tgt` when overwriting a squad. Campionati are stored as `SQ[k].campionati` (array of strings, persisted with the squad). `campBox()` shows the list with remove buttons, opened by the "Campionati" button (`data-tc`, state `campOpen`) in `team0()`, shown before "Edita efficienze". `data-ac` adds a campionato from `input[data-ni=camp]`; `data-rc` removes at index. `d.sv` requires at least one campionato for existing squads (`S.sq !== null`, `isCoach()`); new squads skip this check. `S.camp` (persisted field in `freshMatch()`/`persist()`) stores the selected campionato for the current match; it is a required dropdown in `pre()` — a squad with no campionati or an empty selection disables the start button. `histInfo`/`histOut` in `server.js` include `camp` so the archive index carries it. `team()` now has a fifth sub-screen slot: `campOpen&&isCoach()?5:tgtOpen?4:...`; `data-bk` closes `campOpen` first if open.
- Multi-match totals: the "Global stats" section lives in the Squadra tab, under "Gestione squadra" (coach only): `globalBox()` shows one `data-hm='<team>'` button per team with archived matches (disabled under 2). It calls `loadMulti(team)` to fetch every archived match of the same team (case-insensitive) into `NET.hcache`, then `multiView()` sums them with `withMatch()`: one row per match and a per-player table (key = shirt number + nick, so a renamed or renumbered player counts as another one) reusing `tabHead()` and `line()`. It reads the full index `NET.idx` (`GET /api/history`, coach only), not the 10 recent ones. **Campionato filter**: tab chips (`data-camp`) above the match list filter by campionato (state `gsCamp`, default `''` = all); they are computed from all archived matches of that team and reset to `''` on `data-hm`. **Match list paging**: only 3 matches are shown by default; `data-gsx` toggles `gsExpanded` to show all. Aggregation always runs over the full filtered list regardless of `gsExpanded`. Each match row has an "Elimina" button (`data-gd`, double tap via `armGd`, `DELETE /api/history/:mid`) to drop test matches; when fewer than 2 remain `NET.multi` is cleared. **Rankings**: `rankingsBox(agg)` appends three sections after the match list: classifica punti/errori (per-player saldo = pts \u2212 errors, sorted descending), efficienza per fondamentale (players with \u22653 events per fundamental), and three per-fundamental ranking tables for Battuta, Attacco, Ricezione (min 3 actions each, sorted by efficiency). **Excel export**: `buildGlobalXls()` (triggered by `data-gxls`) produces two-sheet SpreadsheetML: "Riepilogo" (match list with `camp` column) and "Giocatrici" (per-player totals with a Presenze column `a.g` = number of matches played). `'camp'`, `'gsx'`, `'gxls'` are in `VIEW` (usable read-only). `team()` shows Global stats as sub-screen `k=3` with a "\u2190 Squadra" button (`data-hm=''`); `delStats()` is an `.act.del` button (`data-gt`, `style='margin-left:auto;flex:none;background:var(--minus);border-color:var(--minus);color:#fff'`, double tap via `armGt`) inline in the same header row as the back button \u2014 not a separate full-width button below it. `DELETE /api/history-team/:team` (coach only, case-insensitive) drops every archived match of that team via `delHist()`, clears `NET.hcache` entries, sets `NET.multi=null` and reloads `NET.idx`; it does not touch the saved squad. `data-hs` and switching tab (`data-v`) reset `NET.multi`.
- Historical matches are shown by temporarily swapping them into `S` through `withMatch()`. Stats code must read from `S`, not from a separate parameter.
- Team colour: `COLS` (yellow, teal, blue, black) and `colOf()`; `render()` sets `--tag`, `--tagfg`, `--tagbd`, and `--lb` (pink libero with the teal team). The colour is saved in the squad (`SQ[..].col`) and in the match (`S.col`). The opponent name is required to start a match.
- Scout UX helpers: `wake()` (called by `render()` and `visibilitychange`) holds a Screen Wake Lock (`WL`) while a match is open in the Scout tab, needs HTTPS. `add()` vibrates (`navigator.vibrate`, 25 ms, double for `-`/Fallo). Undo sets `undoMsg` (shown in `.last.um` for 2.5 s). The `?` button at the end of the `.fund` row and the legend itself (with a ✕) both carry `data-lg`, which toggles `legOff` (memory only, no storage). The top "Termina scout" is hidden when the match is over (the big one in `scoreRow()` stays). The status bar shows a short label (`.lks`, `data-lkx`) that expands to the detail for 4 s (`NET.lkx`); the live-match list (no open match) is always shown in full.
- "Termina scout" (`data-leave`, double tap via `armLm='lv'`) does `flush()` then `release()` and returns to the live list; the match is not archived. The Squadra menu has no end/exit buttons.
- Stats: the match chips come from `histBar()`: one per other live match (`NET.live`, read-only via `loadLive()`, no lock, refreshed in `tick()` every 3 s while Stats is open) and one per archived match. `loadLive()` puts a snapshot with `live:1` in `NET.hcache`, so `withMatch()` shows it; `expBox()` hides Riprendi/Elimina for it. With no open match, Stats opens the only live match, otherwise the latest archived one.
- Charts are SVG strings inside `charts()`; each card has `data-zm` and `zoomPaint()` shows a zoomed copy (state `zoomK`). The print CSS gives 2 A4 landscape pages: 7 small charts plus quick indicators, then (`.kw`, `break-before:page`) the tables and the player board. Keep it at 2 pages when adding charts.
- FIPAV substitution rules live in `trySwap()`/`bench()`: `MAXSUB=8` per set (counted from `S.subs`), and a pair (out, in) can swap at most twice per set (substitute and return, `closed()`), on top of the existing `S.pair` rule that a returning player replaces only her substitute. Keep the limits in `MAXSUB`.
- Substitutions are logged in `S.subs` as `[set, rallyPointsInSet, outIdx, inIdx]` by `trySwap()`; `trendSvg()` draws them as hollow circles. `subs` is in `persist()`, `freshMatch()`, `hydrate()`, the archive snapshot, `withMatch()` and `loadLive()`; old matches simply have none.
- "Riprendi scout" (`data-rop`, coach only) calls `POST /api/match {a:'reopen', m}`: the server refuses with 409 `error:'live'` if any live match exists, sets `archived:false` (or rebuilds the state from the `HIST` snapshot if the match is gone from `MATCHES`), grants the lock and removes it from `HIST`. The client then calls `openLive()` and sets `reo=mid`, which stops `checkEnd()` from re-archiving a match already at 3 sets; the lineup is chosen again.
- Credits (`credits(false)`, `[data-r=cr]`) appear only on the login screen, not in the inner pages. The optional logo `public/image/Scouty-Logo.jpg` (name is case-sensitive) is probed with an `Image()` and injected into `[data-logo]` only if it loads, so never reference it with a plain `<img>` (it would show a broken icon). Images in `public/` ship in the Docker image, so adding one needs a rebuild.
- Data lives in a bind mount `./data:/data` (not a named volume). The container never runs as root: `docker-compose.yml` sets `user: "${DATA_UID:-1000}:${DATA_GID:-1000}"`, so `data/` must be owned by that exact numeric uid:gid (names do not matter; `www-data` is usually 33, not 1000). If `data/` is missing Docker creates it as root and the container loops in `Restarting`; `server.js` then exits with `Cartella dati non scrivibile`. `setup.sh` fixes the owner automatically only when run as root, otherwise it stops and prints the `sudo chown` command: never make it use `sudo` silently and never switch the container to root to "fix" this. `data/` is git-ignored and excluded from the build via the root `.dockerignore`.

- Archive: Stats shows only the 10 most recent archived matches as chips (`histSummary()`, `HIST_RECENT`, in `NET.hist`), with a hint to the Squadra menu when there are 10. The full archive is the "Archivio partite" section of the Squadra tab, under Global stats, for coach and scoutman (`isCoach()`): `archSec()` (title) wraps `archBox()`: team filter (`data-at`, `arT`, list via `arList()`), a month row `.arh` (`data-am` prev/next jumps to the nearest month that has matches, disabled when none; `arY`/`arM`; no year chips), and `.arw` with a compact calendar (days with matches are buttons, `data-ad`, `arD`, tapping the selected day clears it) plus the month/day list (`data-hs`, newest first, `.arr` rows with the result coloured win/loss). On phones the calendar is hidden until the 📅 button (`data-acal`, local state `arCal`) opens it above the list; from 700px wide it is always shown in a 240px right column and the button is hidden. Choosing a match with `data-hs` from the Squadra tab switches to Stats (`S.view='stat'`, closes roster/threshold editors). The full index `NET.idx` (`loadIdx()`) is loaded lazily by `globalBox()` and set to `null` by `setHv()` whenever the server `hv` changes (every response that returns `hist` also returns `hv`). The `data-*` actions are in `VIEW` (usable read-only). The calendar CSS (`.cal`, `.calg`, `.cd`, `.arl`) is in `app.css`. **Archive navigation**: `arOpen` is preserved when the user navigates back to the Squadra tab so they land where they left off. In the `d.hs` handler do not reset `arOpen`; in the `d.v` handler use `if(d.v!=='team')arOpen=false` (only reset when going to Scout or Stats, not when returning to team). The explicit "← Squadra" button in the archive view (`data-ar=''`) is the only way to close `arOpen` intentionally. When `arOpen&&isCoach()`, `stat()` prepends a "← Archivio" `data-v='team'` button before `histBar()` so the user can navigate back from Stats without hunting for the tab.

- CSS pitfall — red delete buttons: `.act.del` alone does **not** produce a red button; the red background is only defined on `.act.go.del`. Adding `go` also forces `height:50px` and `font-size:18px` (from `.act.go`). When you need a red button at the standard `act` height (44 px), apply the colour via inline style instead: `style='background:var(--minus);border-color:var(--minus);color:#fff'`. Add the armed glow separately: `${armed?';box-shadow:0 0 0 3px var(--card),0 0 0 6px var(--minus)':''}`. Keep `.del` in the class for semantic clarity but rely on the inline style for the actual colour.
